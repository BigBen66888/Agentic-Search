# 从零环境开始：Kaggle/公司服务器完整运行步骤

本文假设机器上只有 Linux、Python 和 NVIDIA 驱动，仓库中没有数据、模型和索引。所有大文件都放在外部目录，例如 /data/search_r1，不写入 GitHub 仓库。

## 0. 机器和目录检查

    nvidia-smi
    df -h
    python3 --version
    mkdir -p /data/search_r1
    cd /path/to/Search_R1_refine

如果没有 GPU，不能按本项目的多卡 veRL 训练路径运行；可以先做数据处理和 CPU 单元测试。

## 1. 创建 Python 环境

    python3 -m venv .venv
    source .venv/bin/activate
    python -m pip install --upgrade pip setuptools wheel

Kaggle 也可以使用已有 conda 环境，但必须记录 Python、CUDA、torch、transformers、vLLM 和 veRL 版本。

## 2. 安装基础依赖

    pip install -r requirements/00-base.txt

验证：

    python -c "import datasets, pandas, pyarrow, requests; print('base dependencies: OK')"

## 3. 安装 GPU 版 torch

下面示例对应 CUDA 12.1 wheel：

    pip install -r requirements/01-torch-cu121.txt

服务器 CUDA 12.1 不等于必须安装本机 CUDA toolkit；PyTorch cu121 wheel 会带对应 runtime，但 NVIDIA 驱动必须足够新。若驱动不兼容，先升级驱动或按 PyTorch 官方页面选择匹配 wheel。验证：

    python - <<'PY'
    import torch
    print("torch:", torch.__version__)
    print("cuda available:", torch.cuda.is_available())
    print("gpu count:", torch.cuda.device_count())
    for i in range(torch.cuda.device_count()):
        print(i, torch.cuda.get_device_name(i))
    PY

要求 gpu count 至少为 1；正式多卡训练建议 4 或 8 卡。

## 4. 安装检索和改写依赖

    pip install -r requirements/02-retrieval.txt

验证：

    python -c "import faiss, transformers; print('retrieval dependencies: OK')"

## 5. 安装 veRL、Ray、vLLM 训练依赖

    pip install -r requirements/03-verl-training.txt

参考 Search-R1 和 veRL 对 vLLM、transformers、torch 的版本约束。若服务器已有可运行的参考 Search-R1 环境，优先复用该环境，不要在同一个环境里随意升级 torch/vLLM。

验证：

    python -c "import ray; print('ray:', ray.__version__)"
    python -c "import vllm; print('vllm:', vllm.__version__)"
    python -c "import verl; print('verl import: OK')"

## 6. 安装本仓库

    pip install -e . --no-deps

    python scripts/check_env.py

运行不依赖数据的 smoke：

    PYTHONDONTWRITEBYTECODE=1 python scripts/smoke_test.py
    pytest -q

## 7. 下载 7 个 QA 数据集

这一步会把 HuggingFace 数据集缓存到外部目录/缓存目录，不会写入仓库：

    python scripts/download_data.py \
      --data-dir /data/search_r1 \
      --qa-only

脚本会逐个打印 nq、triviaqa、popqa、hotpotqa、2wikimultihopqa、musique、bamboogle 的准备状态，并生成 /data/search_r1/download_manifest.json。

## 8. 过滤、查询改写、难度分层

先不启用改写，确认原始数据字段：

    python scripts/prepare_data.py \
      --data-dir /data/search_r1

确认完成后，再用本地小模型做离线改写。模型会下载到 HuggingFace cache，不写入仓库：

    python scripts/prepare_data.py \
      --data-dir /data/search_r1 \
      --rewrite-model Qwen/Qwen2.5-1.5B-Instruct \
      --max-variants 2 \
      --max-total-multiplier 2.5

过程会输出 train/eval/rejected/rewrite 数量、过滤率、有效样本倍率和 easy/medium/hard 分布。检查：

    ls -lh /data/search_r1/processed
    cat /data/search_r1/processed/data_stats.json

确认 test/dev 没有改写，也没有参与阈值调参。

## 9. 下载 Wikipedia 语料并建立索引

下载语料到外部目录：

    python scripts/download_data.py \
      --data-dir /data/search_r1 \
      --corpus

根据实际下载目录找到 JSONL 语料，然后建立 Dense 和 BM25 索引：

    python scripts/build_indices.py \
      --data-dir /data/search_r1 \
      --corpus /data/search_r1/corpus/wiki-18/wiki-18.jsonl \
      --model intfloat/e5-base-v2 \
      --batch-size 64

Dense embedding 会按 batch 打印进度；最终生成：

- /data/search_r1/indices/e5_flat.faiss
- /data/search_r1/indices/doc_manifest.jsonl
- /data/search_r1/indices/bm25.pkl

Wikipedia 体积和索引体积很大，执行前检查磁盘和 GPU 显存。

## 10. 启动 RRF 检索服务

    python scripts/serve_retriever.py \
      --dense-index /data/search_r1/indices/e5_flat.faiss \
      --manifest /data/search_r1/indices/doc_manifest.jsonl \
      --bm25-index /data/search_r1/indices/bm25.pkl \
      --model intfloat/e5-base-v2 \
      --rrf-k 60 \
      --port 8000

另开终端检查：

    curl http://127.0.0.1:8000/health
    curl -X POST http://127.0.0.1:8000/retrieve \
      -H "Content-Type: application/json" \
      -d '{"queries":["Who wrote Hamlet?"],"topk":3}'

## 11. 多卡 veRL GRPO 训练

先确认 Ray 和 GPU：

    ray start --head
    ray status
    nvidia-smi

B1：原始 0/1 reward：

    python scripts/train_grpo.py \
      --data-dir /data/search_r1 \
      --model Qwen/Qwen2.5-3B \
      --reward-mode binary \
      --n-gpus 8 \
      --nnodes 1 \
      --max-steps 50 \
      --dry-run

确认输出命令和路径后，去掉 dry-run：

    python scripts/train_grpo.py \
      --data-dir /data/search_r1 \
      --model Qwen/Qwen2.5-3B \
      --reward-mode binary \
      --n-gpus 8 \
      --nnodes 1 \
      --max-steps 50 \
      --execute

B2：多级 reward：

    python scripts/train_grpo.py \
      --data-dir /data/search_r1 \
      --model Qwen/Qwen2.5-3B \
      --reward-mode multi \
      --n-gpus 8 \
      --nnodes 1 \
      --max-steps 50 \
      --execute

第一次只跑 50 steps 或 5%–10% 数据，用来检查显存、检索服务、reward、KL、NaN 和 checkpoint。正式训练前再增加 steps/epochs。

## 12. 在线评测

准备一个模型 Agent 服务，提供：

    POST /generate
    {"prompt": "..."}
    -> {"text": "<think>...</think><search>...</search><information>...</information><answer>...</answer>"}

运行：

    python scripts/evaluate_online.py \
      --data-dir /data/search_r1 \
      --agent-url http://127.0.0.1:9000/generate \
      --retriever-url http://127.0.0.1:8000/retrieve

输出会写入 /data/search_r1/artifacts：

- eval_traces.jsonl：逐题 action trace
- eval_summary.json：按 source 汇总的答案、证据、格式、效率、token、延迟

B0、B1、B2 必须使用相同 test/dev、相同 RRF 配置和相同评测脚本。
